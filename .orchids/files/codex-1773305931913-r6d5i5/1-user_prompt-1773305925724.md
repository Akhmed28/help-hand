
Project context:
This is an AI-powered Vibe Coding platform (HelpHand) — similar to Replit, Lovable, and Cursor. It has two parts:

Landing page — user enters a prompt via text or microphone, clicks a button to start
Editor/IDE — AI processes the prompt and generates a website or app


Screenshot description of the bug:
The attached screenshot shows a completely black / very dark navy screen (#0a0a0f range) — totally empty, no text, no UI, no loader, no animation. The app is fully frozen. This appears after clicking the submit button on the landing page.

Current broken behavior:

User opens landing page
User speaks into microphone → speech is transcribed to text (e.g. "создать сайт")
User clicks the submit / "Создать" button
Screen goes completely black and freezes — no navigation, no loading indicator, nothing
App is unresponsive — no way to proceed without refreshing the page


Root cause possibilities to investigate:
1. Failed route navigation rendering a blank page:

The router is attempting to navigate to /editor or a new route
But the target component/page fails to mount (due to a crash, missing dependency, or undefined prop)
React/Vue/Next.js renders a blank screen when a component throws an error during mount with no error boundary
Fix: Add an ErrorBoundary component around the editor route to catch and display errors instead of showing blank screen

2. Black screen is a transition/animation overlay that never resolves:

There is a fullscreen overlay (dark background) used as a page transition effect
It activates on button click but never disappears because:

Navigation failed silently
A Promise or async function never resolved
An API call on navigation init is hanging or throwing


Fix: Add a maximum timeout of 3 seconds to force-hide the overlay regardless of navigation state

3. Speech-to-text race condition causing a crash:

When prompt comes from microphone, the transcribed text may still be undefined or null at the moment the button is clicked
Passing null as prompt to the next page causes the editor component to crash on mount
Fix: Validate that prompt text is not empty/null before navigating. If empty, show an inline error message instead of navigating

4. Missing or broken editor page component:

The editor route exists in the router but the component file has an import error, syntax error, or missing module
This causes a silent crash and renders nothing
Fix: Check browser console (F12) for red errors at the moment of the black screen. Fix any module import errors in the editor component

5. Environment variable or API key missing on editor init:

The editor page tries to initialize an AI/API connection immediately on mount
If the API key or environment variable is missing/undefined, it throws an unhandled error
This crashes the component before anything renders
Fix: Add null checks and fallback error states for all environment variables used on editor mount


Immediate fixes to apply:
1. Wrap the editor route in a React ErrorBoundary that shows a visible error message instead of blank screen
2. Add console.log statements at every step of the button click handler to trace exactly where it stops
3. Add a 3-second fallback timeout on any transition overlay to force-show the editor regardless
4. Validate prompt value before navigation — if null/undefined/empty, do not navigate
5. Check browser console for errors the moment the black screen appears and fix all red errors
6. Ensure the editor component has a safe default state if no prompt is passed

Expected result after fix:

Button click → brief transition (optional) → editor loads fully
If something goes wrong → visible error message, NOT a black screen
Prompt is pre-filled in the editor and generation starts automatically

Do not change:

Landing page design or layout
Backend API logic
Any other routes or features
